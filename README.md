# Stock Trading Discord 투자위원회

Discord 봇 5개가 각각 별도 Codex CLI 세션을 유지합니다. `종목-토론`이나 `전략-연구`에서 “다들 의견 줘”, “토론해봐”라고 말하면 공통 서버가 발언을 순서대로 다음 세션에 전달합니다.

TradingView에서는 외부 제공자의 `Lazy Alpha Indicator`를 사용합니다. 이 저장소는 지표가 보낸 Webhook JSON을 받아 모의주문 위험을 별도로 관리하며, 지표 소스나 유료·비공개 자료를 포함하거나 재배포하지 않습니다. 신호 해석의 로컬 기준 문서는 제공받은 `docs/tradingview-webhook-v6.2.md`이며 Git에는 포함하지 않습니다.

별도 사용자가 공용 Discord 매매신호를 받아 자신의 키움·한국투자증권 모의계좌로 실행하는 방법은 [`docs/account-executor.md`](./docs/account-executor.md)를 참고하세요.

지금까지의 단계별 구현 내용과 설계 결정은 [`docs/development-history.md`](./docs/development-history.md)에 정리되어 있습니다.

## 면책 및 비공식 프로젝트 안내

이 저장소는 개인 포트폴리오와 교육·모의투자 목적으로 만든 비공식 프로젝트입니다. `Lazy Alpha Indicator` 제공자와 제휴하거나 공식 인증을 받은 구현이 아니며, 특정 금융상품의 매수·매도 권유나 수익 보장을 제공하지 않습니다. 실제 투자 판단과 손실에 대한 책임은 사용자에게 있습니다.

프로젝트에 등장하는 투자자 이름은 각 투자 철학을 학습·비교하기 위한 AI 페르소나 표현입니다. 해당 인물이나 유족·소속사와 제휴하거나 공식 인증을 받은 서비스가 아닙니다. 또한 OpenAI, Discord, TradingView, 키움증권 및 Telegram과 제휴하거나 이들로부터 보증받은 프로젝트가 아닙니다. 각 서비스의 이름과 상표는 해당 권리자에게 있습니다.

키움·한투 실계좌 주문 어댑터는 구현되어 있지만 기본 잠금 상태이며, 기본 동작은 주문을 만들지 않는 `SHADOW` 모드입니다. 외부 서비스의 이용약관과 데이터 라이선스를 확인한 뒤 사용하세요.

## 1. Discord 봇 만들기

Discord Developer Portal에서 애플리케이션과 봇을 5개 만듭니다.

- 드러켄밀러 관점 AI
- 오닐 관점 AI
- 미너비니 관점 AI
- 리버모어 관점 AI
- 쿨라메기 관점 AI

각 봇의 **Bot > Privileged Gateway Intents > Message Content Intent**를 켜고, 같은 서버에 초대합니다. 필요한 권한은 `View Channels`, `Send Messages`, `Read Message History`입니다.

## 2. 설정

```bash
cd Stock-Trading
npm install
cp .env.signal.example .env.signal
cp .env.account.example .env.account
```

`.env.signal`에는 공통 Discord·TradingView 설정을, `.env.account`에는 사용자 이름과 키움·한투 모의계좌 설정을 입력합니다. 실제 설정 파일은 채팅이나 Git에 올리지 마세요.

기본 Codex 설정은 `gpt-5.6-sol`과 `high` 추론 강도입니다.

```text
CODEX_MODEL=gpt-5.6-sol
CODEX_REASONING_EFFORT=high
CODEX_WEB_SEARCH=live
```

## 3. 실행

```bash
npm run start:all
```

새 iTerm 창에 공통 신호 서버, ngrok, 계좌 주문 실행기가 각각 보이는 탭으로 실행됩니다. `.env.account`가 없으면 계좌 주문 실행기 탭은 열지 않습니다. 백그라운드 프로세스는 만들지 않으며, 각 탭에서 로그를 확인하고 `Ctrl+C`로 개별 종료할 수 있습니다. 다음 문구가 나오면 TradingView에 넣을 **전체 웹훅 URL이 클립보드에 복사된 상태**입니다.

```text
TradingView 웹훅 URL 복사 완료: https://your-domain.ngrok-free.dev/webhook/<secret>
```

터미널에는 비밀 경로를 숨겨서 표시합니다.

한 프로필만 따로 실행할 때는 아래처럼 사용합니다.

```bash
npm run start:signal
npm run start:tunnel
npm run start:executor
```

현재 구조에서 `.env.signal`은 TradingView 수신·신호 분류·Discord 대화를 담당하는 공통 프로필이고, `.env.account`는 Discord의 공통 매매 의도를 읽어 사용자의 키움·한투 계좌에서 다시 계산·주문하는 계좌 프로필입니다. 증권사 이름이 아니라 역할 기준으로 나눈 것이므로 `.env.kiwoom`과 `.env.kis`는 사용하지 않습니다.

```text
TradingView → ngrok → 공통 신호 서버 → Discord 매매신호
                                          ├→ 사용자A 계좌 실행기 → 키움·한투
                                          └→ 사용자B 계좌 실행기 → 키움·한투
```

ngrok에는 Discord 봇이나 주문 코드가 없고 외부 요청을 로컬 수신기로 전달하기만 합니다. `매매신호`는 주문 접수 결과가 아니라 공통 전략 게이트를 통과한 계좌 중립 실행 의도입니다. 각 사용자 실행기는 같은 종목과 방향을 받되 현금·보유량·종목 비중을 자기 계좌에서 다시 계산하므로 사용자와 증권사별 수량·차단 결과가 달라질 수 있습니다.

## 명령어 한눈에 보기

터미널 명령어는 프로젝트 폴더에서 실행합니다.

| 명령어 | 용도 |
|---|---|
| `npm run start:all` | 공통 신호 서버·ngrok·선택적 계좌 실행기를 보이는 iTerm 탭으로 실행 |
| `npm run start:signal` | 공통 신호 서버 실행 |
| `npm run start:tunnel` | ngrok 고정 터널 실행 및 웹훅 URL 복사 |
| `npm run start:executor` | `.env.account` 사용자별 키움·한투 계좌 실행기 실행 |
| `npm run test:webhook-live` | 주문 없는 테스트 신호를 수신기·Discord·계좌 실행기로 전송 |
| `npm run test:account-readonly-e2e` | 위와 같은 주문 없는 계좌 종단간 시험(실계좌 설정 시에도 조회만 수행) |
| `npm run self-test` | 전체 코드 자체 점검 |
| `npm run kiwoom:check` | 현재 설정된 키움 모의·실계좌 인증·계좌 연결 확인(주문 없음) |
| `npm run kis:check` | 현재 설정된 한투 모의·실계좌 인증·계좌 연결 확인(주문 없음) |
| `CONFIRM_MOCK_ORDER=AAPL-1-USD npm run kiwoom:smoke-order` | 영업일에 해외 모의계좌 AAPL 1주 `$1` 지정가 접수·취소 시험 |
| `npm run telegram:login` | Telegram 사용자 계정 최초 1회 로그인 |
| `npm run telegram:list` | 설정한 Telegram 뉴스·시황 채널 확인 |
| `npm run telegram:collect` | 전날 채널 글을 Markdown으로 즉시 수집 |
| `npm run telegram:collect -- 2026-08-09` | 지정 날짜 글을 다시 수집 |
| `npm run portfolio:refresh` | 공개 투자자 자료와 무니 자료를 각각 즉시 갱신 |
| `npm run setup-discord` | Discord 카테고리와 채널 자동 생성 |
| `npm start` | `start:all`과 동일하게 보이는 iTerm 탭으로 전체 실행 |
| `codex login status` | Codex CLI 로그인 확인 |
| `Ctrl+C` | 실행 중인 봇과 터널 종료 |

## Discord 채널 자동 생성

드러켄밀러 봇 역할에 `채널 관리` 권한을 잠시 켠 다음 실행합니다.

```bash
set -a
source .env.signal
set +a
npm run setup-discord
```

카테고리와 채널이 생성된 뒤에는 드러켄밀러 봇의 `채널 관리` 권한을 다시 꺼도 됩니다. 이미 존재하는 항목은 중복 생성하지 않습니다.

신호 채널은 시장별로 다음 다섯 개를 사용합니다.

- 미국: `#미국-전체신호`, `#미국-관찰신호`, `#미국-진입신호`, `#미국-청산신호`, `#미국-매매신호`
- 국내: `#국장-전체신호`, `#국장-관찰신호`, `#국장-진입신호`, `#국장-청산신호`, `#국장-매매신호`

`전체신호`에는 유효한 TradingView 신호를 모두 기록하고, 같은 신호를 성격에 따라 `관찰신호`, `진입신호`, `청산신호` 중 하나에도 보냅니다. `매매신호`에는 승인 대기·관찰 신호를 제외하고 공통 전략 게이트가 `PAPER_ENTRY`, `PAPER_ADD`, `PAPER_PARTIAL_EXIT`, `PAPER_EXIT`로 확정한 실행 의도만 추가로 보냅니다. 키움 주문 접수 성공 여부는 이 분류에 영향을 주지 않습니다.

Codex CLI는 현재 저장된 ChatGPT 로그인을 재사용합니다. 먼저 `codex login status`가 `Logged in using ChatGPT`인지 확인하세요.

## 사용법

```text
오닐, 이 종목을 CAN SLIM 기준으로 분석해줘
리버모어는 지금 기다려야 한다고 봐?
드라켄 밀러와 미너비니는 이 시장을 어떻게 봐?
모두들 오늘 시장에서 중요한 소식 있어?
야, 오늘 특별한 소식 없어?
현재 반도체 업종의 위험과 기회를 같이 토론해줘
대화 새로 시작
매매 상태 보여줘
계좌 상태 보여줘
사용자A 계좌 상태
계좌 최근 주문 보여줘
투자자 포폴 새로 갱신해줘
그만
```

- `@` 없이 이름만 적어도 해당 AI가 답합니다. 여러 이름을 적으면 여러 AI가 각각 답합니다.
- 특정 명령어를 외울 필요 없이 `다른 사람들 의견은 어때?`, `나머지 사람들도 말해줘`, `각자 어떻게 생각해?`처럼 복수 의견을 자연스럽게 요청하면 앞선 발언을 읽으며 남은 AI들이 한 차례의 공동 토론을 진행합니다.
- 아무도 지칭하지 않은 일반 메시지는 질문 주제에 맞는 AI 한 명이 답하고, 애매한 후속 질문은 직전에 답한 AI가 이어갑니다.
- 모든 AI는 같은 채널의 최근 대화를 함께 읽습니다. 한 AI가 다른 관점이 꼭 필요하다고 판단하면 다른 AI 한 명에게만 구체적으로 질문할 수 있으며 연쇄 호출은 하지 않습니다.
- `그만`, `멈춰`, `대화 그만`, `여기까지`만 단독으로 보내면 진행 중인 답변과 추가 AI 호출을 중단합니다. 다음 사용자 메시지부터 다시 응답합니다.
- `대화 새로 시작`은 현재 채널에서 다섯 AI의 대화 기억을 초기화하고, `도움말 보여줘`는 자연어 명령 안내를 표시합니다.
- `매매 상태 보여줘`는 공통 신호 게이트를 조회합니다. `계좌 상태` 또는 `[사용자 이름] 계좌 상태`는 그 사용자 실행기의 연결 설정을, `계좌 최근 주문`은 저장된 계좌별 모의주문을 조회합니다. 매매 모드·중지·재개처럼 공통 상태를 바꾸는 명령은 안전을 위해 `!trade` 형식을 유지합니다.
- 계좌 실행기 자동매매는 `!account auto on`, `!account auto off`, `!account auto status`로 켜기·끄기·확인할 수 있습니다.
- `#시장-브리핑`과 `#매매일지`의 이름 없는 메시지는 드러켄밀러가 기본 응답합니다.
- `#관심종목`은 공유된 TradingView 워치리스트 전체를 `회사명 (티커)` 형식으로 정리합니다. 매일 08:15에 추가·삭제를 동기화하며 Discord 글자 제한을 넘으면 여러 메시지로 나눕니다. 이 목록은 자동 알림·자동매매 대상 수와 별개입니다.
- `#알람설정`은 알람 전용 TradingView 공유 워치리스트를 서비스 시작 시와 매일 08:20에 갱신합니다. 다섯 AI는 알람·알림 설정 질문에 이 목록을 공통 기준으로 사용합니다. TradingView의 비공개 알람 화면은 공식 API로 직접 조회할 수 없으므로, 실제 활성 알람 종목과 공유 워치리스트를 같은 목록으로 관리합니다.
- 사용자별 `#주문승인`에는 해당 계좌 실행기의 BUY 승인 대기와 증권사 주문 접수만 기록합니다. `사줘`, `둘다`, `키움만`, `한투만`, `안 사`처럼 자연어로 대상 계좌를 정합니다.
- 사용자별 `#체결로그`는 키움·한투의 부분체결·체결·취소·거부·주문 실패와 사용자 BUY 승인 거부 사유를 자동 기록합니다.
- 사용자별 `#매매일지`는 실제 체결이 완료된 주문을 한 주문당 하나의 상세 카드로 기록합니다. 연결 시험 주문은 제외합니다.
- 주문승인·체결로그·매매일지·포트폴리오의 종목명은 증권사별 원문 이름 대신 같은 `한글명 / 영문명 (티커)` 기준으로 통일합니다.
- `#전략-연구`는 사용자가 직접 연구 내용을 기록하는 공간입니다.
- `#주요인사-포트폴리오`는 드러켄밀러·버핏·캐시 우드·마이클 버리·조지 소로스·레오폴드 아셴브레너·피터 틸의 13F, 피터 린치의 확인 가능한 공식 공개 자료, 낸시 펠로시의 하원 거래공시, 도널드 트럼프의 OGE 재산공개를 하루마다 확인해 상태판을 수정합니다. 13F 인물은 비중 1% 이상 종목을 비중순으로, 펠로시·트럼프는 공개 거래·자산의 금액 범위와 기준일을 `한글 회사명(티커)` 형식의 별도 카드에 표시합니다.
- `#기관-포트폴리오`는 시타델·블랙록·뱅가드·스테이트스트리트·피델리티·캐피털그룹·JP모건·골드만삭스·모건스탠리·르네상스 테크놀로지스의 최신 SEC 13F에서 비중 1% 이상 종목을 비중순으로 정리합니다. Discord 한도를 넘으면 기관별 메시지로 나눠 기존 상태판만 수정합니다.
- 사용자별 포트폴리오 채널은 연결된 키움·한투 모의계좌의 현재 보유 종목을 같은 상태판 메시지에 반영합니다. 체결 수량이 바뀌면 즉시 갱신하고, 매매가 없어도 기본 하루 한 번 다시 조회합니다. 실제 채널명은 `.env.account`의 `ACCOUNT_PORTFOLIO_CHANNEL`로 정합니다.
- 무니는 같은 채널의 별도 상태판 메시지에서 최근 31일의 무니인사이트 Markdown·PDF를 바탕으로 실제 매입·보유, 관심 종목, 단순 언급을 구분합니다. 이 문맥은 다섯 봇이 다음 답변부터 함께 읽습니다.
- 보낸 메시지를 수정하면 같은 메시지 담당 AI가 수정된 내용으로 다시 답합니다.
- 각 AI의 독립 Codex 세션 기억에 더해, 현재 Discord 채널의 최근 12개 대화를 공용 문맥으로 읽습니다.
- AI가 다른 AI를 실제로 멘션하면 최대 5회까지 서로 대화할 수 있습니다.
- `종목-토론`이나 `전략-연구`에서 여러 사람의 의견을 자연스럽게 요청하면 다섯 세션이 한 차례만 순서대로 의견을 냅니다. 이미 한 AI가 답한 뒤 `다른 사람들 의견`을 요청하면 그 AI를 제외한 나머지만 답합니다.
- 종목명·티커를 포함해 공동 토론을 요청하면 저장된 실제 TradingView 웹훅에서 해당 종목의 마지막 Lazy Alpha 지표를 공통 자료로 전달합니다. 현재 상태를 직접 조회하는 것이 아니므로 수신 시각과 경과시간을 함께 표시하며, 기록이 없으면 공개 종목 정보만 검색해 토론합니다.
- 워치리스트 공동 토론은 최근 웹훅을 받은 종목별 마지막 상태를 최대 20개까지 비교합니다. 이는 TradingView 계정의 워치리스트 전체 목록이 아니라 실제 수신 기록 기준입니다.
- 종목명이나 티커를 적은 질문은 어느 대화 채널에서든 최대 10종목의 키움 현재가·당일 시가·고가·저가와 최근 TradingView 신호·수신 시각·SL을 함께 전달합니다. 정확한 Lazy Alpha 베이스 저점은 별도 값이 없으면 추측하지 않고 마지막 SL을 무효화 참고선으로 구분합니다.
- AI가 응답을 준비하는 동안 Discord의 `입력 중…` 표시를 주기적으로 갱신합니다.
- 평일 `08:30`, `15:40`, `22:00`에는 `#시장-브리핑`에서 드러켄밀러가 최근 사용자 자료와 별도로 웹 검색한 지수·금리·환율·수급·뉴스·향후 5거래일 주요 이벤트를 확인해 자동 브리핑합니다. 자동 브리핑은 누적 문맥으로 느려지지 않도록 매번 새 AI 세션을 사용하며, 시간초과를 피하려고 자동·수동 브리핑 모두 문서 본문만 읽습니다.
- 자동 브리핑과 사용자가 요청한 공동 토론은 iCloud `주식` 폴더에서 최근 7일 이내 추가·수정된 PDF 중 최신 3개를 함께 참고합니다. 이미지형 PDF는 macOS 내장 OCR로 앞부분 5쪽을 읽으며 원문은 수정하지 않습니다.
- 한 번 정상적으로 다룬 파일은 처리 기록에 남아 이후 **자동 브리핑**에서는 다시 선택되지 않습니다. 사용자가 직접 질문하면 이미 다룬 자료도 다시 참고할 수 있으며, 파일이 수정되면 자동 브리핑에서도 새로운 자료로 인식합니다.
- Discord에는 참고한 파일명이 먼저 표시됩니다. 문서의 시점 민감한 내용은 웹의 공식 자료로 재확인하고, 빠른 매매신호 검토에는 이 자료 읽기를 넣지 않습니다.
- 자동 브리핑 시간과 채널은 `.env.signal`의 `AUTO_BRIEFING_*` 설정으로 바꿀 수 있습니다.
- `!reset`은 해당 봇의 Codex 세션만 새로 시작합니다.
- 다섯 봇에는 주문 실행 권한이 없습니다.

최근 자료의 기간·개수·읽을 페이지 수는 `.env.signal`의 `RESEARCH_LOOKBACK_DAYS`, `RESEARCH_MAX_FILES`, `RESEARCH_MAX_PAGES`로 바꿀 수 있습니다. 바로 토론하려면 Discord에서 다음처럼 입력합니다.

```text
최근 추가된 반도체 자료를 바탕으로 핵심 주장, 반대 근거, 확인할 종목을 다들 토론해봐
```

## Telegram 뉴스·시황 일일 수집

`TELEGRAM_CHANNEL_MATCH`에 지정한 뉴스·시황 채널 중 최근 활동 채널을 자동 선택하므로 방 이름이 주기적으로 바뀌어도 설정을 다시 바꿀 필요가 없습니다.

1. [Telegram API 개발 도구](https://my.telegram.org/apps)에서 본인 계정의 `api_id`와 `api_hash`를 발급합니다.
2. 두 값을 `.env.signal`의 `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`에 입력합니다. 채팅이나 Discord에는 붙여넣지 않습니다.
3. 프로젝트 폴더에서 `npm run telegram:login`을 한 번 실행하고 전화번호, Telegram 앱 인증 코드, 2단계 인증 비밀번호를 입력합니다.
4. `npm run telegram:list`로 현재 허용 채널이 잡히는지 확인합니다.
5. `npm run telegram:collect`로 전날 자료 저장을 시험합니다.
6. 성공하면 `.env.signal`의 `TELEGRAM_ENABLED=false`를 `true`로 바꾸고 `npm run start:all`을 다시 실행합니다.

활성화 후 매일 `00:10`(한국 시간)에 전날 본문·캡션·링크를 Markdown으로 저장합니다. 사진과 동영상 원본은 내려받지 않습니다.

```text
iCloud Drive/주식/텔레그램/2026-08-09_뉴스시황.md
```

새 Markdown은 기존 PDF와 같은 최근 자료로 인식되어 자동 브리핑과 사용자가 요청한 공동 토론에서 참고됩니다. 실시간 웹 검색을 완료하고 정상 본문을 반환한 자동 브리핑만 실행·자료 검토 완료로 기록합니다. 실패·시간초과·검색 불가 안내문은 완료로 처리하지 않으며, 사용자가 직접 질문하면 자료를 재검토할 수 있습니다.

`.telegram-session`은 로그인 권한이 담긴 비밀 파일이므로 공유하거나 Git에 올리지 마세요. 로그아웃 또는 세션 폐기가 필요하면 Telegram 설정의 **기기**에서 해당 세션을 종료한 뒤 이 파일을 삭제하고 다시 로그인합니다.

## 프로젝트의 자동매매 안전 모드

아래 정책은 `Lazy Alpha Indicator`의 공식 매매 원칙이 아니라 이 프로젝트가 Webhook 신호 위에 별도로 적용하는 로컬 위험 관리 규칙입니다. 공통 신호 서버는 계좌 중립 매매 의도까지만 만들고, 사용자별 계좌 주문 실행기가 자기 현금·보유량·종목 비중을 다시 계산합니다. 실계좌 기능은 구현되어 있지만 기본 잠금 상태입니다.

```text
!trade         사용 가능한 명령어 표시
!trade status  공통 신호 게이트 상태 확인
!trade halt    신규 진입 즉시 중지
!trade resume  신규 진입 재개
!trade shadow  신호 판단과 모의 포지션만 기록
!trade paper   유효 신호를 사용자별 계좌 실행기로 전달
!trade off     모든 진입과 청산 판단 중지
계좌 상태 / 사용자A 계좌 상태  사용자별 실행기 연결 상태 확인
계좌 최근 주문 보여줘  사용자별 키움·한투 최근 주문 확인
사줘 / 둘다 / 키움만 / 한투만 / 안 사  사용자별 #주문승인에서 BUY 결정
다들 의견 줘 / 토론해봐  현재 채널에서 다섯 AI가 한 차례 순차 토론
AI이름 !reset  해당 AI의 Codex 대화 세션 초기화
```

- 5종목 보유 중인 경우 여섯 번째 신규 진입은 차단합니다.
- 기존 종목을 전량 청산하면 빈 슬롯에 다른 종목이 진입할 수 있습니다.
- 손절가가 없거나 현재가 이상인 매수, 확신도 `D`, 중지 상태의 신규 진입은 차단합니다.
- 실계좌 주문은 사용자별 계좌 실행기에서 지원하며 기본 잠금입니다. `KIWOOM_ENV=live` 또는 `KIS_ENV=live`와 `ACCOUNT_LIVE_TRADING=true`를 함께 설정해야 열립니다.
- 자동매매가 켜진 실계좌는 확신도 A·S, 일봉 강세, EMA 정배열, 200일선 위를 모두 만족한 BUY만 자동 주문합니다. 200일선 위의 혼조·EMA 미정렬 BUY는 축소 계산 후 해당 실계좌만 사용자 승인을 기다립니다. 위험을 줄이는 SELL은 자동 처리하며 AI 답변은 승인 조건이 아닙니다.

## TradingView 웹훅 수신기

현재 수신기는 신호를 검증·정규화·기록하고 Discord에 알립니다. `PAPER_AUTO`에서는 안전장치를 통과한 일반 진입·부분청산·전량청산 신호가 국내·미국 모의주문으로 이어집니다. `SHADOW`에서는 주문 없이 판단과 기록만 남깁니다.

국내·미국 신호 채널에는 요약과 함께 TradingView가 보낸 원본 지표 필드를 빠짐없이 표시합니다. `CHECK` 참고 알림은 자동주문을 만들지 않습니다. `1차 분할청산`·`TP1`은 보유 가능 수량의 25%, `2차 분할청산`·`TP2`는 남은 보유 가능 수량의 50%를 모의매도하며, 같은 단계 신호는 포지션당 한 번만 실행합니다. 계산 결과가 1주 미만이면 전량 매도로 바꾸지 않고 차단합니다.

### 비밀 경로

웹훅 주소의 마지막 비밀값은 프로젝트 루트의 `.webhook-token` 파일에 있습니다. 최초 실행 때 64자리 무작위 값이 자동 생성되며 `.gitignore`에 등록되어 있습니다.

```text
https://your-domain.ngrok-free.dev/webhook/<.webhook-token의 값>
```

값을 터미널에 노출하지 않고 클립보드에 복사하려면 다음을 사용합니다.

```bash
pbcopy < .webhook-token
```

전체 URL을 화면에 표시하지 않고 바로 복사하려면 다음을 사용합니다.

```bash
printf '%s/webhook/%s' "$NGROK_PUBLIC_URL" "$(tr -d '\r\n' < .webhook-token)" | pbcopy
```

평소에는 직접 조합할 필요가 없습니다. `npm run start:all`이 공개 주소와 비밀 경로를 합친 전체 URL을 자동으로 클립보드에 복사합니다. 이 URL은 비밀번호처럼 취급하고 채팅, 화면 캡처, Git에 올리지 마세요.

### 왜 수신 주소가 로컬인가

봇 화면의 `127.0.0.1`은 정상입니다. 외부에 수신기를 직접 공개하지 않고 ngrok이 TradingView 요청을 이 Mac으로 전달합니다.

```text
TradingView → NGROK_PUBLIC_URL → 127.0.0.1:8787 → Discord 봇
```

ngrok 무료 계정에 배정된 개발 주소는 재실행해도 유지됩니다. TradingView 알림의 웹훅 URL은 최초 한 번만 고정 주소로 저장합니다.

### TradingView 알림 설정

- 지표: `Lazy Alpha Indicator: JSON 전용`
- 조건: `어떤 alert() 함수 호출`
- 인터벌: 차트와 같게(현재 4시간봉)
- 웹훅 URL: `npm run start:all`이 복사한 전체 URL 붙여넣기
- 메시지: 지표가 만든 JSON을 그대로 사용하고 임의로 수정하지 않기

알림 생성 자체는 테스트 신호를 보내지 않습니다. 실제 지표 조건이 발생할 때 전송됩니다.

### 안전한 연결 테스트

```bash
npm run test:webhook-live
```

이 테스트는 TradingView를 거치지 않고 로컬 수신기, Discord, 계좌 실행기 연결을 확인합니다. 실제 종목 형식의 진입 신호지만 `paper_order_test=true` 안전장치가 계좌 실행기에서 주문 생성을 차단합니다.

고정 공개 주소까지 확인하려면 다음처럼 실행합니다.

```bash
WEBHOOK_ORIGIN="$NGROK_PUBLIC_URL" npm run test:webhook-live
```

### TradingView 실제 알람→국내 모의계좌 1주 테스트

[`docs/tradingview-mock-order-test.pine`](./docs/tradingview-mock-order-test.pine)은 `005930` 차트에서만 실행되며 봉당 한 번 테스트 신호를 보냅니다. 실제 주문은 서버의 잠금 파일이 시장가 매수 1주·1회로 제한합니다. 평소에는 반드시 아래 설정을 `false`로 둡니다.

```text
PAPER_ORDER_TEST_ENABLED=false
PAPER_ORDER_TEST_SYMBOL=005930
```

실제 시험 직전에만 `true`로 바꾸고 재시작한 뒤 Discord에서 `!trade paper`를 입력합니다. TradingView 알림 조건은 `Kiwoom Mock Order One-shot Test` → `어떤 alert() 함수 호출`이며 웹훅 URL은 `npm run start:all`이 복사한 값 중 `/health`가 응답하는 현재 터널 주소를 사용합니다. 한 번 주문을 시도하면 `.paper-order-test-lock.json`이 남아 같은 설정으로는 다시 주문할 수 없습니다. 시험 후 TradingView 테스트 알림을 삭제하고 설정을 다시 `false`로 돌린 뒤 재시작합니다.

### 현재 프로젝트 안전 설정

다음 수치와 필터는 지표 제공자의 권고값이 아니라 모의투자 검증을 위해 이 저장소에서 정한 기본값입니다. 지표의 화면 표시나 알람은 주문 지시가 아니며, 수신 신호가 아래 게이트를 통과한 경우에만 모의주문 후보가 됩니다.

- 현재 연결 환경: 키움·한투 모의계좌. 실계좌는 별도 잠금 해제 전까지 비활성
- 기본 자동매매 모드: `SHADOW`; Discord에서 `!trade paper`를 입력한 동안만 일반 신호 모의주문
- 동시 보유 한도: 5종목
- 한 종목 투자금 한도: 계좌 평가액의 20%
- 기본 거래당 위험: 계좌 평가액의 0.5%(확신 등급에 따라 조정)
- 국내·미국 BUY·SELL 신호: 사용자별 키움·한투 모의계좌의 현금·보유·비중을 기준으로 수량·투자금·예상 손실을 다시 계산. 계좌 자동매매가 켜져 있으면 즉시 모의주문하고, 꺼져 있으면 자동 주문을 멈추며 BUY는 수동 승인 가능
- 미국 BUY는 프리장에는 주문하지 않고 정규장·애프터장에 시도하며, SELL은 프리장·정규장·애프터장에 시도합니다. 증권사가 BUY를 거절하면 최대 5일간 예약 후 다음 주문 가능 시간에 재검증합니다.
- 국내주식도 장전 시간외에는 SELL만, 정규장·장후 시간외 종가·시간외 단일가에는 BUY·SELL을 시도하고, 주문 가능 시간 밖 BUY는 예약합니다.
- 4시간봉 BUY 신호: `daily_trend=BULL`, 일봉 EMA 정배열, 일봉 200일선 위일 때만 주문 허용
- 일봉 혼조 또는 EMA 미정렬이지만 200일선 위: 기본 위험 절반·한 종목 최대 10%로 계산. 자동매매가 켜진 모의계좌는 자동 진입하고 실계좌는 `주문승인`에서 사용자 승인을 기다림
- 일봉 약세 또는 200일선 아래: BUY 차단
- 기존 보유 종목 추가 진입: 기존 평가금액과 신규 주문금액 합계가 계좌 평가액의 20% 이내일 때만 허용
- 기존 보유 종목 추가 진입: 키움 잔고의 매입금액·평가손익으로 수익 상태까지 확인된 경우에만 허용하며, 손실·본전 또는 손익 확인 불가는 차단
- 피라미딩 추가 진입: 현재 포지션 주수를 추정하지 않고 계좌별 주문 이력의 최초 진입 실제 체결수량을 기준으로 1차 50%, 2차 25% 주문. 각 단계는 앞선 추가매수 체결 확인 후 한 번만 허용하고, 수량·비중 위험 한도가 더 작으면 그 한도를 적용
- 국내 정규장 진입: 최유리 IOC로 최대 2회 시도하고 미체결 잔량은 취소하며 시장가로 전환하지 않음. 국내 정규장 청산도 최유리 IOC로 최대 2회 시도하며, 급락 손절만 남은 수량을 시장가로 전환. 미국 진입: 주문 직전 현재가의 0.5% 위와 신호가 중 낮은 가격을 상한 지정가로 사용. 미국 청산: 신호 가격 지정가
- 최종 청산·돌파 청산·급락 손절·모멘텀 SELL·PEG Invalid·진입 만료: 보유 가능 수량 전량 모의매도
- `1차 분할청산`·`TP1`: 보유 가능 수량의 25% 모의매도
- `2차 분할청산`·`TP2`: 남은 보유 가능 수량의 50% 모의매도
- 같은 부분청산 단계 중복 신호: 증권사 계좌별 현재 포지션에서 한 번만 실행. 전량청산 체결 또는 새 진입 접수 시 단계 기록 초기화, 1주 미만 계산 시 차단
- `부분 익절고려`·`상승 모멘텀 종료`: 고정 비율 신호가 아니므로 계속 검토만 기록
- TradingView 감시 가능 종목: 최대 20개
- 실계좌 주문: 지원, 기본 잠금 (`ACCOUNT_LIVE_TRADING=false`)
- `종목-토론`: 체결 후 토론이 아니라 셋업·VCP·PEG Start 등 진입 전 CHECK 신호만 자동 토론
- AI 토론: 주문 승인 조건이 아니며 모의주문과 독립적으로 실행
- 처리 기록: `webhook-events.jsonl`, `trading-decisions.jsonl`; 체결 일지는 신호명·등급·SL을 함께 기록

기존 수동 보유처럼 이 실행기의 최초 진입 체결 기록이 없는 포지션은 최초 수량을 추정하지 않고 피라미딩을 차단합니다. 전량청산 체결 후에는 다음 최초 진입부터 새 기준을 만듭니다.

### 실계좌 전환 정책

실계좌 연결 기능은 구현되어 있으며 기본 잠금 상태입니다. 자동매매가 켜져 있으면 확신도 A·S이면서 일봉 강세·EMA 정배열·200일선 위인 `BUY`는 정상 크기로 자동 주문합니다. 200일선 위지만 일봉이 혼조이거나 EMA가 미정렬인 `BUY`는 축소 계산 후 `#주문승인`에서 사용자가 승인한 경우에만 주문합니다. 손절·최종청산·부분청산 같은 보유 위험을 줄이는 `SELL`은 자동 실행합니다. `부분 익절고려`와 `상승 모멘텀 종료`는 명확한 수량이 없으므로 자동주문하지 않습니다.

계좌별 `자동매매 켜`·`자동매매 꺼` 스위치는 실계좌에서도 사용합니다. 현재 연결은 키움·한투 모두 모의이며 `ACCOUNT_LIVE_TRADING=false`라 실계좌 잠금은 유지됩니다.

실계좌의 인증·잔고·현금·Discord 신호 전달은 `ACCOUNT_READ_ONLY=true`, `ACCOUNT_LIVE_TRADING=false`로 잠근 실행기에서 `npm run kiwoom:check`, `npm run kis:check`, `npm run test:account-readonly-e2e`로 주문 없이 확인할 수 있습니다. 읽기 전용 모드는 일반 신호·승인·예약·미완료 주문 재처리를 건너뛰고 `paper_order_test=true` 신호만 받습니다. 주문 접수·체결 조회·취소까지의 실제 종단간 검증은 실제 주문이 발생하므로 별도 종목·수량·가격과 실행 승인을 정한 뒤에만 수행합니다. `kiwoom:smoke-order`는 코드에서도 모의환경만 허용합니다.
