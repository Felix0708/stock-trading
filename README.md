# Stock Trading

TradingView 웹훅을 검증·기록하고 Discord에서 신호를 검토하며, 사용자별 증권사 계좌 실행기로 연결하는 TypeScript 프로젝트입니다. AI 대화와 주문 실행은 분리됩니다.

## 범위와 주의사항

- 특정 지표의 구매·구독은 프로젝트의 필수 조건이 아닙니다. 사용할 지표와 데이터 이용 권한은 운영자가 선택합니다.
- **아무 지표나 웹훅 주소만 붙이면 호환되는 것은 아닙니다.** 현재 수신 형식과 신호 매핑에 맞는 데이터가 필요하며, 다른 형식은 별도 어댑터와 검증이 필요합니다.
- 공개 코드의 기본 위험 정책은 구현 예시이지 투자 권고나 특정 운영자의 실제 설정이 아닙니다.
- 키움·한국투자증권 연결을 지원하지만 모의·실계좌의 주문 시간과 기능은 다릅니다. 실계좌는 기본 잠금이며, 코드 구현과 실제 계좌 검증은 별개입니다.
- 교육·모의투자 목적의 비공식 프로젝트입니다. 수익이나 체결을 보장하지 않습니다. 투자자 이름은 AI 페르소나를 구분하는 표현이며 해당 인물·기관·서비스 제공자와 제휴하거나 인증받은 서비스가 아닙니다.
- 외부 지표 소스, 유료 자료, 실제 계좌 내역과 개인 운영 기록은 배포하지 않습니다.

## 구조

```text
TradingView → HTTPS 터널 → 공통 신호 서버 → Discord
                                              ├→ 사용자 A 계좌 실행기
                                              └→ 사용자 B 계좌 실행기
```

공통 서버는 신호를 검증하고 계좌 중립 의도를 전달합니다. 계좌 실행기는 자기 계좌의 현금·보유·미체결 주문을 확인해 수량과 실행 여부를 결정합니다. AI 설명은 주문 승인이나 체결 증거가 아닙니다.

```text
src/app/          Discord 봇·공통 서버
src/ai/           대화·신호 검토
src/signals/      입력 검증·신호 정규화·상태 처리
src/brokers/      증권사 연결
src/executor/     계좌별 승인·실행·복구·성과
src/trading/      위험 계산·주문 추적
src/integrations/ 외부 서비스 연동
src/research/     선택적 자료 수집
scripts/          실행·점검 도구
tests/            합성 데이터 기반 회귀 검사
docs/             공개 사용법과 기술 계약
```

## 설치와 설정

Node.js 버전은 `.nvmrc`를 기준으로 맞춥니다. 전체 실행 도우미는 macOS·iTerm·ngrok 환경을 대상으로 합니다. 이 도구들이 설치되어 있어야 합니다.

```bash
cd Stock-Trading
nvm install
nvm use
npm install
cp .env.signal.example .env.signal
cp .env.account.example .env.account
```

| 파일 | 입력할 내용 |
|---|---|
| `.env.signal` | 본인 Discord 서버·봇, 웹훅, 선택적 AI·자료 수집 설정 |
| `.env.account` | 사용자 표시명, 신뢰 채널·발신자, 증권사 키·계좌, 모의/실계좌 선택 |
| `docs/shared-trading-context.md` | 선택적 로컬 AI 대화 기준. 없으면 공개 예시를 사용 |

실제 설정 파일은 Git에서 제외합니다. 예시의 사용자명·채널명·경로·시간은 직접 정하며 다른 운영자의 값을 복사하지 않습니다. 모델과 추론 강도는 `CODEX_MODEL`, `CODEX_REASONING_EFFORT`로, 정기 브리핑 전용 설정은 `CODEX_BRIEFING_*`로 정합니다. 선택한 모델이 현재 로그인에서 지원되는지 확인하세요.

Codex CLI는 본인 ChatGPT 로그인을 사용합니다. `codex login status`로 확인하며, 로그인을 공유하거나 인증 파일을 배포하지 않습니다.

### Discord

현재 구성은 투자 철학별 AI 봇 5개입니다. Discord Developer Portal에서 봇을 만들고 `Message Content Intent`를 활성화합니다. 일반 실행 권한은 `View Channels`, `Send Messages`, `Read Message History`입니다. 채널 자동 생성 도구를 사용할 때만 채널 관리 권한이 추가로 필요합니다.

`.env.signal`의 봇 토큰·서버·소유자 설정과 `.env.account`의 사용자별 채널·신뢰 발신자 설정을 입력합니다. 채널 이름은 예시이며 실제 구성에 맞춰야 합니다. 선택적으로 `npm run setup-discord`를 사용하고, 생성 후 불필요한 관리 권한은 회수합니다.

미국 신호 화면은 요약·SEPA·4시간봉 리포트와 관찰·진입·추매·관리·청산·모멘텀·PEG로 구분합니다. 기존 구성 이관은 `npm run setup-discord -- --us-only`로 변경 목록을 먼저 확인하고, `--apply`를 추가해 적용합니다. 주문 전달 채널의 ID·권한과 과거 메시지는 보존합니다. 화면용 카드에는 주문 전달 정보를 넣지 않습니다.

요약은 최근 72시간의 실제 수신분 중 최신 일봉 거래일/4시간봉을 집계하며, 1분마다 변경분을 기존 카드에 반영합니다. 지표의 봉 시각이 없는 구형 기록은 수신 시각 기준이라고 표시합니다. 최초 이관은 분류별 최근 5건만 화면에 다시 표시하며 주문을 재실행하지 않습니다. SEPA 사전점검은 최근 종목 10개까지 제공하고, 새 관찰·진입·추매 신호의 AI 상세 분석은 종목당 미국 날짜 기준 하루 1회입니다. AI 분석은 공개 신호 필드와 웹 자료만 사용하며 계좌 정보와 분리합니다. 자료가 부족하면 종합 등급을 산정하지 않고, AI 결과를 주문 규칙에 자동 반영하지 않습니다. 검증은 `npm run test:us-signal-cards`로 실행합니다.

## 지표와 알림 연결

1. 사용 권한이 있는 지표나 직접 작성한 스크립트를 선택합니다.
2. 출력 JSON을 [수신 필드·타입](src/signals/webhook-schema.ts) 및 [신호 매핑](src/signals/signal-normalizer.ts)과 대조합니다. 알 수 없는 신호나 방향 불일치는 주문을 막습니다. 없는 위험 정보를 임의로 채워 통과시키지 마세요.
3. 지표의 실제 알림 방식에 맞춰 조건을 선택합니다. `alert()` 기반 스크립트라면 `Any alert() function call`을 사용하지만 모든 지표에 공통인 설정은 아닙니다.
4. 종목·시간봉·봉 확정 조건을 본인의 전략에 맞춰 정합니다. 현재 코드에는 4시간봉·일봉을 다르게 처리하는 규칙과 두 시간봉 기준 알람 점검이 있습니다. 다른 시간봉을 사용하려면 이 경로도 함께 검증해야 합니다.
5. 본인 HTTPS 웹훅 주소를 설정합니다. 메시지는 검증된 출력 계약을 따라야 하며, 지표나 입력을 변경한 뒤에는 알림도 재생성하고 수신을 확인합니다.
6. 먼저 `SHADOW`와 주문 없는 연결 시험으로 검증하고, 그 뒤 별도 승인한 모의주문 시험을 수행합니다.

관심종목과 알람 대상 목록은 `TRADINGVIEW_WATCHLIST_URL`, `TRADINGVIEW_ALERT_WATCHLIST_URL` 등에 본인 목록을 지정합니다. 공유 워치리스트는 실제 알람 활성·만료의 증거가 아닙니다. 종목 수·시간봉별 알림 수와 구독 한도는 본인 계정에서 확인하세요.

[합성 웹훅 예시](docs/webhook.example.json)는 필드 확인과 테스트용입니다. 실제 시세·투자 신호가 아니며 운영 알림 메시지로 그대로 사용하지 않습니다.

## 실행

```bash
npm run start:all
```

공통 신호 서버·터널·선택적 계좌 실행기를 보이는 iTerm 탭으로 실행합니다. 각 탭에서 로그를 확인하고 `Ctrl+C`로 종료합니다. 개별 실행은 `start:signal`, `start:tunnel`, `start:executor`를 사용합니다.

전체 실행 도우미가 복사하는 웹훅 주소에는 비밀 경로가 들어갑니다. 비밀번호처럼 취급하고 채팅·스크린샷·Git에 공개하지 마세요. 서버의 `127.0.0.1`은 터널 뒤의 로컬 수신 주소입니다.

네트워크 치명 오류만 기존 실행 탭에서 제한적으로 재시작합니다. 일반 코드·설정 오류와 사용자 종료는 자동 재시작하지 않습니다. 재시작이 누락 신호의 체결이나 무중단 운영을 보장하지는 않습니다.

## 점검과 주요 명령

| 명령 | 용도 |
|---|---|
| `npm run typecheck` | 타입 검사 |
| `npm run self-test` | 합성 데이터·로컬 테스트 서버를 사용하는 회귀 검사 |
| `npm run test:webhook-live` | 로컬 수신기→Discord→계좌 실행기 연결 확인. 시험 플래그로 주문 차단 |
| `npm run kiwoom:check` / `npm run kis:check` | 설정된 계좌의 인증·잔고 연결 확인, 주문 없음 |
| `!trade status` / `!trade shadow` | 공통 신호 처리 상태 확인 / 주문 없는 관찰 |
| `!account auto status` / `!account auto off` | 본인 계좌 자동매매 상태 확인 / 중지 |
| `계좌 상태` / `계좌 최근 주문` | 본인 실행기의 상태·기록 조회 |
| `다들 의견 줘` / `그만` | AI 공동 검토 요청 / AI 응답 중지 |

`그만`은 AI 대화 명령으로 자동매매 중지 명령을 대신하지 않습니다. 모의주문을 실제로 만드는 시험은 [테스트 안내](docs/README.md)의 별도 절차를 따르세요. 실제 계좌는 읽기 전용 확인부터 시작하고, 종목·수량·가격·위험 한도를 별도로 승인하기 전 잠금을 풀지 않습니다.

## 선택 기능

- 정기 브리핑: `AUTO_BRIEFING_*`로 채널·시각·시간대를 선택합니다.
- 최근 자료·Telegram: `RESEARCH_*`, `TELEGRAM_*`로 본인이 열람·처리할 권한이 있는 자료만 지정합니다. 특정 유료 커뮤니티나 개인 폴더는 필요하지 않습니다.
- 공개 투자자·기관 포트폴리오: 공개 공시 기준의 참고자료이며 현재 보유나 실제 평단가를 보장하지 않습니다.
- Stock-Briefing: 본인 배포/서비스 주소와 개인 연동 토큰을 설정합니다. 계좌별 보유·성과·자산 기록을 분리하며, 공시·뉴스·AI 설명은 주문 조건에 넣지 않습니다.

### 주문과 독립된 자산 조회

`sh start-asset-reader.sh`는 `.env.account`의 명시된 키움·한투 mock/live 자격증명으로 잔고만 조회하고 기존 Stock-Briefing 연동 토큰으로 전송합니다. 주문·취소 API는 허용하지 않으며 `KIWOOM_ENV`, `KIS_ENV`, `ACCOUNT_LIVE_TRADING`을 변경하지 않습니다. 기본 실행기 시작 시 함께 시작되고 중복 실행은 잠금으로 막습니다. 시장 운영 시간대에 시간당 조회하며 컴퓨터·프로세스가 꺼져 있으면 수집하지 않습니다.

원·달러·엔(KRW/USD/JPY)의 현금과 주식 평가액만 합산하며 다른 통화는 제외합니다. 키움 KRW/USD는 기존 결제예정 현금, JPY는 증권사 통화별 평가 응답을 사용합니다. 같은 계좌의 원화 현금은 한 번만 더합니다. 한투 모의 통화별 현금이 전체 보고액과 맞지 않으면 검증된 기존 총액을 보존하고 통화별 0원으로 대체하지 않습니다.

전용 기록은 `.runtime/selected-currency.evidence.json`이며 최초 실행 시 기존 자산 UUID 매핑만 복사합니다. 주문 실행기의 기록 파일과 동시에 쓰지 않습니다. 운영 수신 DB·웹을 먼저 갱신하고, 기존 수집기를 종료한 뒤 `sh start-asset-reader.sh --force`로 최초 조회·전송합니다. 실행 중인 수집기와 일회성 스크립트를 동시에 실행하지 않습니다. IP 허용목록은 증권사 설정이며 핫스팟의 공인 IP가 바뀌면 키움에서 다시 등록해야 합니다.

일반 실계좌의 국내·미국 보유종목과 ISA 국내 보유종목도 자동 전송합니다. 웹의 ‘증권사 조회’는 수집 방식이고 ‘직접/자동’은 매수 주체이므로, 자동 조회됐다고 자동매매로 분류하지 않습니다. 연동된 잔고는 다시 수기 등록할 필요가 없습니다. ISA 설정·중복 방지·매수 주체 판정·업데이트 순서는 [계좌 자산 동기화 계약](docs/account-equity-sync.md#실계좌-보유종목과-매수-주체)을 따릅니다.

- 세금 참고 추정: 포트폴리오 동기화 후 실계좌의 올해 미국주식 매도 집계(부분 매도 포함)를 `/api/sync/tax-estimate`로 별도 전송합니다. 모의계좌는 제외하고, 체결시각·매도 전 평단 미확인은 누락 건수로 전달합니다. 웹은 직접 매매 기록과 합산해 현재 환율·비용 전 참고값을 계산하므로 신고용 세액이 아닙니다. 송신 코드 갱신은 실행기 재시작 후 적용되며 주문 조건은 변경하지 않습니다.
- 외부 상태 감시: 서버 상태만 공개하고 계좌 식별자·잔고·인증 정보는 내보내지 않습니다.
