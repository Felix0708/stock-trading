# 주문 없는 진입 타이밍 비교

운영 모의매매의 진입·청산·수량 규칙은 변경하지 않는다. 별도 주문, 계좌, 감시 작업을 만들지 않고 기존 신호 수신 및 성과 보고 경로를 사용한다.

## 수집 범위

- 신규 정상 신호부터 기존 `forward-policy-study.json` 안에 연구 기록을 추가한다. 과거 기록은 재생하거나 새 표본으로 바꾸지 않는다. 테스트·복구 신호는 제외한다.
- 처음 수집한 정책 해시를 기준으로 고정한다. 코드/포함된 설정의 해시가 달라지면 타점 연결 연구만 `PAUSED_POLICY_CHANGE`로 중지한다. 운영 주문을 중지하거나 설정을 되돌리는 기능이 아니다. 새로운 비교 기간 시작은 별도 검토가 필요하다.
- 계좌별 실행 설정의 기준 해시도 별도로 보존한다. 공통 신호 서버와 계좌 설정은 다를 수 있으며, 계좌 설정 변경은 보고의 `accountPolicyComparison`에 표시한다. TradingView 내부 지표 설정 자체를 이 해시로 검증하는 것은 아니다.
- 모든 일봉 신규 진입 후보를 기록해 선택 편향을 피한다. 각 후보와 이후 최초 4시간봉 신규 진입 신호를 연결한다. 추가매수 신호는 새로운 진입으로 간주하지 않는다.
- 다음 거래일 정규장 마감을 연구용 기한으로 쓴다. 기존 거래소 캘린더의 휴장·미국 조기마감·서머타임을 반영하며, 일정이 미확인이면 연결하지 않는다. 이는 실제 TradingView 알림의 세션/봉 마감 시각을 확인했다는 뜻이 아니다.
- 청산·진입 무효/만료 신호는 후보를 종료한다. 동일 시각 또는 역순 도착은 새로운 선행 근거로 쓰지 않는다. 새로운 일봉 진입은 이전 후보를 대체한다.
- 계좌의 실제 대기·차단·만료·주문 결과와 이유를 별도 이력으로 보존한다. 같은 상태의 반복 확인은 이력을 늘리지 않는다. 후보 및 후속 신호의 원래 ID로 성과 보고에서 연결한다.

## 해석과 한계

`NEW_4H_SIGNAL`은 새 타점을 관측했다는 뜻이지 매수 가능·접수·체결을 뜻하지 않는다. 새 신호에 현재 계좌 규칙을 가상 적용하는 주문 엔진은 추가하지 않았다. 일봉 후보 전체가 자료이며, 가격/과열 때문에 놓친 사례는 계좌별 실제 사유로 구분한다.

신호 가격 차이는 수익률이 아니다. 호가·봉 중간 가격 경로·가상 체결·수수료가 없으므로 대안 전략의 순수익률과 최대 낙폭은 `null`로 표시한다. 실제 체결 기준 성과는 기존 보고를 사용하되 설정 해시가 다른 거래를 합치지 않는다. 보유 중 설정 변경 거래는 실제 총손익에 남기고 깨끗한 전략 비교에서만 제외한다. 비용 미확인을 0으로 처리하지 않는다.

조회: 기존 주문 채널의 `!account performance` 또는 `계좌 전략 성과 보여줘`. 첨부 보고의 `entryTimingComparison`, `accountSignalOutcomes`, `accounts`, `accountEquity`에서 각각 관찰 연결, 계좌 처리 이력, 실제 거래 성과, 계좌 자산 성과를 확인한다. 누적 데이터로 우월성을 판단하기 전에는 대안 주문을 활성화하지 않는다.

## 실제 성과와 전략 비교용 표본

- 모의계좌는 국내·미국, 증권사 구분 없이 최대 보유 종목 수 제한을 적용하지 않는다. `MAX_OPEN_POSITIONS`는 실계좌에만 적용한다. 가용 현금·종목별 비중·과열·손절·중복 주문 등 나머지 검증은 유지하며, 과거 차단 신호를 일괄 재주문하지 않는다. 이 변경 전후의 성과는 기존 정책 해시별로 구분한다.

- 누적 성과는 실행 지연·장애·정책 변경 거래를 포함한 기존 실제 체결 손익을 유지한다. 평가 사유를 붙인다고 손익을 보정하거나 주문을 재실행하지 않는다.
- 비교 표본은 정책 해시·시간봉·시각 증빙이 있고 실행 영향 사유가 없는 최종청산 거래다. 동일 정책 해시와 통화끼리만 비교하며, 여러 정책의 승률을 합쳐 하나의 전략 승률로 표시하지 않는다. 비용 미확인은 순손익 `null`로 유지한다. 비교 가능은 최적 체결이나 미래 수익의 보장이 아니다.
- 사유는 `MOCK_SESSION_LIMIT`, `SYSTEM_INCIDENT`, `POLICY_CHANGE`, `DATA_INSUFFICIENT`, `EXECUTION_DELAY_UNATTRIBUTED`, `REVIEW_REQUIRED`다. 한 거래에 복수 사유를 붙이되 같은 사유는 한 번만 센다. 유리한 지연 거래에도 동일 기준을 적용한다.
- 미국 모의 신호가 확인된 정규장 밖에서 수신된 경우 거래시간 제한을 표시한다. 이를 지연의 유일한 원인이라고 단정하지 않는다. 국내와 실계좌에 미국 모의 시간표를 적용하지 않는다. 국내도 기록된 장애·정책 변경·자료 부족·원인 미확정 지연은 같은 기준으로 분류한다.
- 새 주문에는 `signalReceivedAt`(신호 수신), `orderRequestedAt`(증권사 클라이언트 호출 직전), `orderAcceptedAt`(접수 응답 확인)을 저장한다. 요청~접수에는 토큰·호출 제한 대기도 포함될 수 있으며 네트워크 송신 순간이나 거래소 접수 시각이라고 부르지 않는다.
- 기존 `lastFillAt`는 체결 수량 증가를 프로그램이 관측한 시각이다. 증권사 증빙의 `evidenceFilledAt`와 구분해 `LOCAL_OBSERVATION`/`BROKER_EVIDENCE`로 표시한다. 과거 `createdAt`, `updatedAt`, `resultAt`를 실제 요청·체결 시각으로 대체하지 않는다. 누적 부분체결 기록이므로 개별 체결별 지연을 복원했다는 뜻도 아니다.
- 신호~요청(확인된 모의 시간제약 제외), 요청~접수, 접수~체결/확인 중 5분 초과는 원인 미확정 지연 검토 표식이다. 주문 취소·재시도·손절 규칙을 바꾸는 시간제한이 아니며, 미체결 대기와 조회 지연을 장애로 단정하지 않는다.
- 디스코드 누적 카드·전략 비교 카드·상세 JSON과 웹 전송용 `performance.evaluation`은 같은 계산 결과를 사용한다. 웹에는 계좌별 집계와 정책·통화별 코호트만 전달하며 개별 주문/신호 식별자·시각 상세는 추가 전송하지 않는다. 과거 웹 자료에 evaluation이 없으면 미수신이지 0건이 아니다. 수신 DB→웹→송신 실행기 순서로 배포한다.
- 가상 체결·승률은 아직 계산하지 않는다. 실제 손익에서 신호가 대비 가격 차이를 다시 차감하지 않는다. 주문 생성 전 차단/승인/예약 결과는 `accountSignalOutcomes`에서 따로 확인한다.
- 웹 평가 집계 전송은 `STOCK_BRIEFING_PERFORMANCE_EVALUATION_ENABLED=true`로 수신 준비 확인 후 활성화한다(기본 false). 비활성일 때도 기존 보유·전체 성과 동기화는 유지된다. 수신 계약 한도인 100개 코호트를 넘으면 평가 필드만 생략하며 전체 상세 비교는 로컬 보고서에 남는다.
