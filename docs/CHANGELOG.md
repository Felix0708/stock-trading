# 공개 개발 기록

소스에서 확인 가능한 기술 변경만 기록합니다. 개인별 설정·운영 결과·보유 종목·금액·계정 식별정보는 포함하지 않습니다. 아래 기능 지원은 모든 실제 계좌의 연결·체결 검증 완료를 뜻하지 않습니다.

## 2026-09-27

### 분석 결과·전체 목록 동기화 경로 보완

- SEPA v3는 일봉 원자료를 직접 조회해 추세 7조건을 계산합니다. 일봉 RS는 지표 제공값이며 IBD 등급으로 표시하지 않습니다. 출처 URL만으로 점수를 승인하지 않고 독립 조회한 인용 원문을 대조합니다.
- 브리핑의 사실·인용·자료 기준일을 구조화하고 원문에 없는 수치를 걸러 재작성합니다. 자료 조회는 승인 범위의 공개 출처로 제한합니다.
- 신호별 실패 격리·기존 로그 기반 재처리·게시 메시지 ID 재사용을 적용했습니다. 대화와 배경 분석을 분리하고 요청 전체 시간과 프로세스 취소를 연결했습니다. 내부 CLI 오류 원문을 일반 대화·자동 분석 채널에 보내지 않습니다.
- 전체 보유 목록 한도를 수신부와 함께 200행으로 확장하고 저장 건수 일치를 확인합니다. 목록 절삭·분할 교체는 하지 않습니다.
- 로컬 회귀 검증과 운영 적용은 별개입니다. 수신 DB 마이그레이션 → 웹 배포 → 해당 로컬 프로세스 재시작 → 실제 수신 확인 순서가 필요하며 이 문서만으로 배포 완료를 의미하지 않습니다.

### 문서와 현재 신호 화면 대조

- 시장별 12개 채널(주간성과·월간결산 포함), 오늘의 시그널의 4시간봉 우선·일봉 대체 조건, 4시간봉 기준 알람 점검을 README에 맞췄습니다.
- Stock-Briefing의 Gemini API 공시 요약·Q&A와 이 저장소의 AGY/Codex 실행 경로는 별개입니다. 모델 변경이나 Git 푸시만으로 다른 서비스의 환경설정·실행 프로세스가 갱신되지는 않습니다.
- 이번 문서 대조는 운영 재시작·Discord 게시·주문 검증을 추가 수행했다는 의미가 아닙니다. 기존 작업의 검증 범위는 아래 각 기록을 따릅니다.

### AI 최종 대체 경로

- 공통 AI 호출에 Codex CLI의 GPT-6 Sol medium을 마지막 대체 경로로 연결했습니다. 일반 대화·브리핑·SEPA가 같은 전환 규칙을 사용합니다.
- 기존 모델이 성공하면 추가 호출하지 않으며 인증·권한 거부·사용자 중지는 대체하지 않습니다. Codex 응답도 완료 이벤트와 최종 본문을 검증합니다.
- 합성 검사에서 3단계 한도 전환·기본 모델 성공·전체 모델 실패·미완료 출력을 확인합니다. 운영 재시작과 실제 채널 검증은 별도입니다.

### 웹 자료 조회 권한과 검증 범위

- headless 웹 조회의 기본 승인 요구가 자동 실행에서 거부되는 원인을 확인하고, 필요한 공개 도메인을 개별 승인하는 운영 절차를 문서화했습니다. 전체 웹 읽기와 모든 도구 자동 승인은 사용하지 않습니다.
- 목록 밖 기업 IR·공시 출처는 도메인과 용도를 확인한 뒤 추가 승인합니다. 권한 거부·누락 자료를 확인된 사실이나 임의 점수로 채우지 않으며, 권한 문제를 모델 전환으로 우회하지 않습니다.
- 전역 규칙이 다른 CLI 세션 및 터미널 통신 범위에도 영향을 줄 수 있음을 명시했습니다. 개인별 허용 목록·인증·계좌 정보는 공개 기록에 포함하지 않습니다.
- 타입검사·AI 응답 검사·봇 자체검사와 개인정보 없는 Sol medium 실제 호출을 통과했습니다. Gemini·Opus의 공개 페이지 조회도 확인했으며, Opus는 첫 검사 실패 후 재검사에서 성공했습니다. 이는 모든 외부 사이트의 안정성을 보장하지 않습니다.
- 이 기록 시점에 수정 코드의 공통 신호 서버 재시작과 실제 Discord 채널 검증은 미완료입니다. CLI 검증과 운영 반영을 구분하며 주문 실행·Stock-Briefing 배포 완료를 뜻하지 않습니다.

### 신호 표시·분석의 근거 검증

- 중첩 웹훅의 상위봉·펀더멘털·사용자 과열 기준을 공통 카드 처리에 연결했습니다. 예시 점수·목표가·섹터를 실제 데이터처럼 표시하던 기본값을 제거했습니다.
- 네 전략 체크를 규칙 기반 부분 점검으로 명시했습니다. 지표 판단과 별도 AI 조사 결과를 구분합니다.
- SEPA 버튼은 정확한 신호 식별자로 분석을 조회하고, 없으면 공개 자료를 조사합니다. 종목 불일치·빈 JSON·출처 누락을 검증하고 한 번 보완 요청합니다. 부분 분석은 종합 등급으로 승격하지 않습니다.
- 자동 브리핑은 사실·해석·반대 근거·결론을 분리하고 질문·멘션·출처 없는 본문은 한 번 재작성 후에도 통과하지 못하면 게시하지 않습니다.
- 성과는 시간봉별로 나누며 중복·테스트 신호와 계산 불가능한 청산을 승률에서 제외합니다. 본전은 별도 표시하고 부분청산을 거래 전체 성과로 합산하지 않습니다.
- 모델 시간초과와 늦은 프로세스 종료의 경쟁을 차단했습니다. 대체 모델의 정상 결과를 이전 프로세스 오류가 덮어쓰지 않습니다.
- CLI가 종료코드 0·SUCCESS를 반환해도 `denied_actions`가 있으면 자료 조회 성공으로 취급하지 않습니다. 웹 읽기 권한은 별도 운영 승인으로 설정해야 하며 모든 도구 자동 승인을 사용하지 않습니다.
- 합성 데이터로 누락값·응답 검증·버튼 클릭·재조회·중복·시간초과를 검사합니다. 로컬 검사 통과는 운영 재시작·실계좌 검증 완료를 의미하지 않습니다.

## 2026-09-18

### 주문과 독립된 읽기 전용 수집

- 주문 실행기와 분리된 수집 경로를 추가했습니다. 허용된 인증·잔고 API만 호출하며 주문·취소 요청은 차단합니다.
- 일반 계좌와 ISA 자격증명을 분리하고, ISA는 국내 잔고만 수집합니다. 모의/실계좌 주문 선택과 실주문 잠금은 변경하지 않습니다.
- KRW/USD/JPY 자산 집계와 개별 보유종목 조회를 구분합니다. 새 보유종목 전송 경로는 일반 실계좌 KR/US 및 ISA KR만 지원합니다.

### Stock-Briefing 보유종목 연동

- 완전하게 조회된 계좌·시장 잔고만 전송합니다. 성공한 빈 잔고와 조회 실패를 구분하며 실패한 범위의 기존 기록은 보존합니다.
- 조회 방식과 매수 주체를 구분합니다. 자동매매 보유 수량은 기존 주문 기록으로 판단하고, 기록 누락·미확정 주문·수량 충돌은 확인 필요로 남깁니다.
- 수신 계약은 수기 원본 보존과 같은 범위의 잔고 중복 합산 방지를 요구합니다. 조회 잔고로 과거 거래나 매수 주체별 취득원가를 만들어내지 않습니다.
- 업데이트 순서는 수신 DB → 웹 → 읽기 전용 수집기 재시작 → 수신 확인입니다. `--force`는 실행 중인 수집기의 잠금을 우회하거나 기존 프로세스를 갱신하지 않습니다. 웹 새로고침도 증권사 재수집을 뜻하지 않습니다.

### 주문 일관성과 복구

- 보유 종목뿐 아니라 매수 미체결과 잔고 반영 전 체결분도 종목 한도에 포함합니다. 기존 초과 보유분을 강제로 매도하지 않습니다.
- 주문 직전 손절 기준 이탈을 재검사하고, 체결 응답의 종목·방향·수량·날짜와 누적 체결량을 검증합니다.
- 재시도·재시작으로 승인 기한을 늘리지 않습니다. 날짜 경과나 미체결 목록에서의 부재만으로 주문 종료를 단정하지 않습니다.

구체적인 계약과 검증 범위는 [계좌 자산 동기화](account-equity-sync.md), [주문 일관성](order-consistency.md)을 따릅니다. 이 기록을 작성하기 위해 계좌 조회·주문·운영 데이터 전송을 실행하지 않습니다.
