# 운영 검증과 외부 감시

이 문서는 설치자가 수행할 검증 절차입니다. 특정 운영자의 실제 계좌·설정·거래·장애 기록이나 현재 서비스 상태를 공개하지 않습니다. 증권사 기능 구현과 실제 접수·체결 검증을 구분합니다.

## 검증 순서

1. `npm run typecheck`, `npm run self-test`로 합성 데이터 기반 회귀 검사를 실행합니다. 실제 증권사 주문은 보내지 않습니다.
2. 본인 지표의 출력 필드·신호·시간봉을 검증기와 정규화 규칙에 대조합니다. 주문 없는 `SHADOW` 및 연결 시험을 먼저 수행합니다.
3. 계좌별 인증·잔고·현금 조회를 읽기 전용으로 검증합니다. 모의·실계좌와 시장별 지원을 각각 확인합니다.
4. 모의 주문 시험은 대상 종목·수량·가격·취소 계획을 정한 뒤 별도로 실행합니다. 실제 접수번호·체결·잔량·취소 확인 없이 성공으로 기록하지 않습니다.
5. 응답 유실, 부분체결, 재시작 복구는 합성 응답으로 검사하고 실제 운영 증빙과 구분해 기록합니다. 오래된 신호를 현재 주문으로 재생하거나 가상 체결로 장부를 맞추지 않습니다.

## 비공개 증빙

계좌별 수신·주문·체결·정산 파일, `.runtime/` 감사 자료, 로컬 운영 이력과 실제 설정은 Git에 올리지 않습니다. 불일치 복구 전 원본을 보관하고 정확한 주문 식별자·증권사 증빙으로 대조합니다. 불명확한 주문을 실패로 단정해 다시 보내지 않습니다.

## 자산과 성과

증권사·계좌·모의/실계좌·통화·자산 범위를 분리합니다. 입출금·비용·관측 자료가 충분히 검증되지 않으면 수익률을 0%로 만들지 않습니다. [자산 동기화 계약](account-equity-sync.md)과 [실행 신뢰성](execution-reliability.md)을 참고하세요. 실제 전체 손익과 전략 평가에서 제외하는 장애 영향 거래를 구분합니다.

## 외부 감시 연결

`.github/workflows/external-health.yml`은 주문 경로가 아닌 `/health`를 점검합니다. 신호 서버와 등록된 계좌 실행기의 연결·갱신 상태를 확인하며 공개 응답에는 계좌·주문 식별자·잔고를 넣지 않습니다.

운영자가 GitHub 비밀값 `MONITOR_HEALTH_URL`, `MONITOR_DISCORD_WEBHOOK`을 설정합니다. 알림 전용 웹훅만 사용하고 증권사 키·전체 봇 토큰은 공유하지 않습니다. 선택적 설정 도구는 `scripts/setup-external-monitor.cjs`입니다. 필요한 채널 권한을 먼저 확인하며 서버 전체 관리자 권한을 요구하지 않습니다.

예약 실행은 지연·누락될 수 있습니다. 장애 알림은 보호주문이나 무중단 보장이 아닙니다. `Ctrl+C`·터미널 종료와 PC·통신 중단 시 로컬 감시도 중단될 수 있습니다.

## 보호주문과 실계좌

로컬 손절 감시와 증권사 서버에 보관되는 STOP은 다릅니다. API 필드가 존재해도 해당 계좌·시장·세션에서 지원된다는 증거는 아닙니다. 모의계좌에서 미지원 응답을 받으면 같은 요청을 반복하거나 다른 주문 방식으로 자동 대체하지 않습니다.

실계좌 잠금, 승인된 정책 지문, 보호주문 지원·유효기간·수량 변경·취소 완료·서버 중단 시 유지 여부를 별도로 확인합니다. 보호주문은 가격·체결을 보장하지 않으며 매수 후 등록 사이에 보호 공백이 생길 수 있습니다. 지원 확인이 없는 신규 진입을 보호된 주문처럼 설명하지 않습니다.

## 변경과 검증 기록

의존성 보안 검사, 타입·회귀 검사, 프로세스 상태 확인을 구분해 수행합니다. 설정 변경·재시작은 정확한 대상만 지정하며 기존 장부와 예약 상태를 보존합니다. 개인별 적용 결과는 로컬 `docs/private/` 등에 보관합니다. 공개 코드의 테스트 통과를 모든 계좌의 실거래 검증으로 해석하지 않습니다.
