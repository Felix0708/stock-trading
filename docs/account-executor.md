# 사용자별 계좌 주문 실행기

공통 신호 서버는 TradingView 신호를 한 번만 받아 Discord의 `국장-매매신호`, `미국-매매신호`에 **계좌 중립 실행 의도**를 게시합니다. 각 사용자는 자기 컴퓨터에서 계좌 주문 실행기만 실행합니다.

```text
공통 신호 서버
  └─ Discord 매매신호
       ├─ 사용자A 실행기 ─ 키움·한투 모의계좌 ─ 사용자A 전용 기록 채널
       └─ 사용자B 실행기 ─ 키움·한투 모의계좌 ─ 사용자B 전용 기록 채널
```

## 다른 사용자가 준비할 것

1. 이 저장소와 Node.js를 설치하고 `npm ci`를 실행합니다.
2. 키움·한투 중 사용할 증권사의 모의 API를 신청합니다.
3. Discord에서 공용 매매신호 채널은 읽을 수 있고, 자기 전용 주문승인·체결로그·매매일지·포트폴리오·시스템상태 채널에는 쓸 수 있게 합니다.
4. `.env.account.example`을 `.env.account`로 복사해 사용자 이름, Discord ID, 모의계좌 키를 입력합니다.
5. 사용하지 않는 증권사는 `EXECUTOR_KIWOOM_ENABLED=false` 또는 `EXECUTOR_KIS_ENABLED=false`로 끕니다.
6. `npm run self-test` 후 `npm run start:executor`를 실행합니다.

다른 사용자 컴퓨터에서는 `start:signal`과 `start:tunnel`을 실행하지 않습니다. 숨은 백그라운드 서비스도 만들지 않습니다.

## Discord에서 보이는 흐름

- 공용 `매매신호`: 종목·방향·손절·신호 품질과 공통 게이트 결과만 표시합니다.
- 사용자별 `주문승인`: 각 계좌의 현금·보유량·20% 비중 제한으로 계산한 예상 수량·투입금액·주문 후 예상 계좌 비중을 표시하고, 증권사 주문 접수 상태까지만 남깁니다.
- `자동매매 켜`: 키움·한투 모의계좌가 BUY·SELL 신호를 각자 다시 계산해 즉시 주문합니다.
- `자동매매 꺼`: 자동 주문을 멈춥니다. BUY는 기존 수동 승인 흐름을 사용할 수 있습니다.
- `사줘` 또는 `둘다`: 가능한 키움·한투 계좌 모두 실행합니다.
- `키움만`, `한투만`: 지정한 증권사만 실행합니다.
- `안 사`, `둘다 ㄴㄴ`: 해당 승인 요청을 취소합니다.
- 사용자별 `체결로그`: 부분체결·체결 완료·취소·거부·주문 실패와 사용자 BUY 승인 거부 사유를 상세 카드로 기록합니다.
- 사용자별 `매매일지`: 체결 완료 주문만 한 주문당 하나의 상세 카드로 기록합니다. `포트폴리오`는 연결된 계좌 결과를 같은 상태판 메시지에 반영합니다. 모든 비중은 주문 수량 계산과 동일하게 현금과 보유 평가액을 합친 국내·미국 계좌별 자산을 분모로 사용합니다.
- 미완료 주문은 30초마다 다시 조회합니다. 체결 수량 변화가 확인되면 즉시 `체결로그`와 `포트폴리오`를 갱신하고, 체결 완료 시 `매매일지`를 기록합니다. 시작 시와 기본 하루 한 번 포트폴리오 갱신은 누락 방지용입니다.
- 주문·예약·포트폴리오 갱신 오류는 `시스템상태`에 짧은 오류 카드로 남기며, 같은 종류의 반복 오류는 30분 동안 중복 전송하지 않습니다.

같은 신호라도 현금·기존 보유·매입 단가·종목 비중이 다르면 수량이나 차단 결과도 달라집니다. 수량을 공통 서버에서 복제하지 않는 이유입니다.

`npm run test:webhook-live`는 실제 종목 형식의 신호를 공통 서버와 Discord를 거쳐 계좌 실행기까지 보내되, `paper_order_test=true` 안전장치로 주문 생성 직전에 차단합니다.

## 상태 확인

사용자별 `시스템상태` 또는 `주문승인` 채널에서 아래처럼 입력합니다.

```text
계좌 명령어 보여줘
계좌 상태 보여줘
사용자A 계좌 상태
계좌 최근 주문 보여줘
자동매매 켜
자동매매 꺼
자동매매 상태
```

`ACCOUNT_EXECUTOR_NAME=사용자A`이면 Discord에는 `사용자A 계좌 주문 실행기`로 표시됩니다. 이름 없는 `계좌 상태`는 현재 실행기가 답하고, `사용자A 계좌 상태`처럼 이름을 붙이면 일치하는 실행기만 답합니다. 시작 시에도 사용자 이름, 활성 증권사, 신뢰 채널 수, 실계좌 차단 여부를 한 번 게시합니다. 현재 상태 메시지는 시작·오류·수동 조회를 기록하며 중앙 서버가 각 원격 컴퓨터를 계속 감시하는 heartbeat는 두지 않습니다.

## 토큰과 채널 ID

- `ACCOUNT_DISCORD_TOKEN`: 공용 신호를 읽고 개인 채널에 기록할 Discord 봇 토큰입니다. 신뢰하는 환경에서는 기존 신호 봇 토큰을 재사용할 수 있지만 별도 토큰이 권한 분리에 더 안전합니다.
- `ACCOUNT_SOURCE_CHANNEL_IDS`: 공용 `국장-매매신호`, `미국-매매신호` 채널 ID입니다.
- `ACCOUNT_SOURCE_BOT_IDS`: 위 신호를 게시하는 봇 ID입니다.
- `ACCOUNT_TARGET_GUILD_ID`: 함께 사용하는 Discord 서버 ID입니다.
- `ACCOUNT_*_CHANNEL`: 이 사용자만의 결과 채널 이름 또는 ID입니다.

`.env.account`와 주문 상태 JSON에는 비밀값·계좌 정보가 있으므로 Git에 올리지 않습니다. 공통 신호 서버의 설정은 `.env.signal`, 사용자별 키움·한투 설정은 `.env.account`만 사용합니다.

키움 접근 토큰은 공식 유효기간인 24시간 동안, 한투 접근 토큰도 응답된 유효기간 동안 로컬의 권한 제한 캐시에 보관해 재사용합니다. 재시작이나 `npm run kiwoom:check`가 유효한 토큰을 다시 발급하지 않으므로 키움 `au10001` 발급 요청 한도와 한투 1분당 1회 발급 제한을 불필요하게 소모하지 않습니다. 한투 모의계좌가 초당 호출 제한 `EGW00201`을 반환하면 공식 예제와 같이 61초 후 한 번 자동 재시도합니다. 캐시 파일은 Git에서 제외됩니다.

`ACCOUNT_AUTO_TRADING=true`는 시작 시 자동매매를 켭니다. Discord 명령으로 바꾼 값은 수신 상태 JSON에 저장되어 재시작 후에도 유지됩니다. 키움·한투 실계좌 API도 지원하지만 기본값은 `mock`이고, `KIWOOM_ENV=live` 또는 `KIS_ENV=live`와 `ACCOUNT_LIVE_TRADING=true`를 함께 설정해야만 실계좌가 열립니다. 실계좌 BUY는 자동매매가 켜져 있어도 항상 Discord 사용자 승인을 거칩니다.

미국주식 BUY는 프리장에는 주문하지 않고 정규장과 애프터장에만 시도합니다. SELL은 프리장·정규장·애프터장에 시도합니다. 증권사가 해당 계좌·환경에서 애프터장 주문을 거절하면 BUY는 최대 5일간 예약하고 다음 주문 가능 시간에 현재가와 계좌 현금·보유량·20% 비중 한도를 다시 계산합니다.

예약 재시도는 키움·한투가 각자 현재가를 조회하며, 만료되거나 다른 발급으로 무효화된 인증 토큰은 한 번 새로 발급해 같은 요청을 재시도합니다. 조회·인증 같은 일시 오류가 발생해도 예약은 삭제하지 않고 다음 세션 재시도를 위해 오류 시각과 사유를 보관합니다.

국내주식도 같은 원칙입니다. 장전 시간외에는 SELL만, 정규장·장후 시간외 종가·시간외 단일가에는 BUY와 SELL을 시도합니다. 정규장 SELL은 키움 `16`, 한투 `15` 최유리 IOC로 주문하고 3초 후 잔량을 한 번 재주문한 뒤에도 남으면 시장가로 전환합니다. 그 밖의 주문은 키움 61/3/81/62, 한투 05/01/06/07 주문 구분을 사용하고, 장전 BUY나 휴장 시간 BUY는 예약으로 유지합니다.
