# 주문 확인 지연과 자동매수 복구 설계

상태: 코드 구현 및 합성 응답 회귀 검증 완료. 배포·실제 주문 취소 완료와는 구분한다.

## 구현 범위

- 기존 inbox의 일시적 확인 대기와 만료를 분리했다. 승인·자동 진입·장 종료 전 검증에 공통 적용하며 원 신호 마감 시각은 늘리지 않는다.
- 기존 VERIFY 예약에도 명시된 실행 마감 시각을 상한으로 적용한다. 정상 장 종료 예약의 기존 정책은 유지한다.
- 정확한 지정가·잔량·손절 기준이 있는 **모의 BUY**만 자금·위험 및 보유 종목 자리를 확보하고 다른 종목을 검토한다. 송신 불명·정정 연결 불명·다른 시장·잔고 불일치는 계속 대기한다. 실제 보유로 넘어간 수량은 장부와 맞아야 하며 임의로 체결 처리하지 않는다.
- 증권사 주문가능금액에 이미 반영된 예약 자금을 정확히 분리하는 API 증빙은 없다. 따라서 계산 가능한 최대 주문 자금을 추가 차감하는 보수적 상한을 적용한다. 이 때문에 필요 이상으로 매수 수량이 줄 수 있지만 자금을 더 쓸 수 있게 추정하지 않는다. 보유 위험과 남은 주문 위험은 중복 집계하지 않는다.
- 합산 손절위험은 기존 모의 정책대로 참고 지표다. 새 한도를 만들거나 기존 실계좌 위험 한도를 완화하지 않는다.
- 주문별 조회 결과를 별도로 기록하고, 한 건의 조회 오류에도 다른 주문 대조는 계속한다. 기존 취소 경로에는 접수/거절/불명 상태를 저장하고 거절·불명 취소를 무조건 반복하지 않도록 했다.
- 기존 진행 카드를 수정해 조회 실패·종료 증빙 미확인·취소 상태·신호 대기 기한을 표시한다. 별도 정기 감시나 작업 큐는 추가하지 않았다.
- 이미 소비된 과거 신호를 대기열에 재삽입하거나 취소에 실패한 과거 주문을 종료 처리하는 작업은 포함하지 않는다.

## 수정 전 확인한 처리 경로

- `account-executor.ts:reconcilePendingBrokerOrders`는 전일 해외 주문을 과거 체결 이력으로 대조한다. 종료 증빙을 찾지 못하면 `reconciliationRequired`를 설정한다.
- `account-evidence.ts:reconciliationPlan`은 잔량이 남은 과거 행을 종료된 주문으로 바꾸지 않는다. 현재 목록에 없거나 날짜가 지났다는 사실만으로 체결·만료를 확정하지 않는 원칙은 유지한다.
- `entry-allocation.ts:allocationRisk`는 소유자에 연결된 계좌 중 하나라도 미확인 주문이 있으면 신규 매수를 모두 차단한다. 이 결과에는 일시적 확인 대기를 나타내는 구분이 없다.
- `account-executor.ts:processInboxBroker`는 일반 차단 결과를 처리 완료로 소비한다. 일시적인 주문 확인 지연으로 막힌 신호도 원래 유효기간 안에서 자동 복구되지 않을 수 있다.

## 1단계: 안전정책을 완화하지 않고 신호 유실 방지

1. 확인 지연과 전략 거절을 결과 코드로 구분한다. 확인 지연에는 `retryable: true`와 차단 원인이 된 내부 주문 참조를 제공한다. 표시 문구를 파싱해 분기하지 않는다.
2. 일시적 확인 대기 신호는 기존 inbox에서 완료 처리하지 않는다. 새 작업 큐나 별도 감시 서비스를 만들지 않고 기존 실행기의 재검토 경로를 재사용한다.
3. 승인 진입·자동 진입·장 종료 예약 전 검증에서 같은 결과를 보존한다. 예약으로 옮기는 경우에도 확인 대기로 인해 기존 신호의 마감 시각을 연장하지 않는다. 정상 장 종료 예약 정책과 확인 장애의 유효기간을 혼동하지 않는다.
4. 복구 시 현재 가격, 기존 가격 상한, 최신 청산/무효 신호, 보유량, 미체결, 현금, 손절 기준을 다시 검사한다. 원 신호 ID를 유지하고 소유자 단위 기존 매수 직렬화 안에서 실행한다.
5. 유효기간이 지나면 `EXPIRED`로 종료한다. 만료 신호의 시각을 현재로 바꾸거나 자동 재생하지 않는다.

## 주문 상태와 조회 상태의 분리

기존 주문 상태는 유지하고 조회 결과에 `lastAttemptAt`, `lastSuccessAt`, `reasonCode`를 둔다. 확인 성공, 조회 실패, 일치 행 없음, 과거 잔량 종료 미확인을 구별한다. 최근 확인 성공은 주문 종료를 뜻하지 않는다.

- 주문 식별: 계좌·환경·시장·종목·매매 구분·주문번호·거래일. 증권사 주문번호 재사용과 정정/취소 원주문 연결을 확인한다.
- 종료 증빙: 정확히 일치하는 체결/취소/거부/만료 기록. API별 필드 의미는 공식 규격과 실제 응답으로 검증한다.
- 현재 주문 목록 부재와 잔고 차이만으로 종료 상태를 만들지 않는다.
- 주문별 조회 실패가 다른 주문의 대조를 중단하지 않도록 분리하되, 증권사별 호출 제한과 기존 직렬화를 유지한다.

## 사용자 취소

- 확인된 기존 실행기 내부 작업 큐에서 취소 의도를 먼저 저장한다. 대상은 원주문과 남은 수량이며 이미 체결된 수량을 매도하지 않는다.
- 취소 접수, 취소 거절, 취소 응답 불명을 구분한다. 접수만으로 `CANCELLED`로 바꾸지 않는다.
- 응답이 불명확하면 취소를 재전송하지 않고 원주문/취소번호로 대조한다. 명확한 거절도 사유 확인 없이 반복하지 않는다.
- 과거 이력에는 잔량이 있고 현재 주문에는 없는 경우, 취소 가능한 주문이라고 단정하지 않는다. 증권사 종료 증빙 또는 명세서 대조 경로로 보낸다.
- 취소 의도는 재시작 후에도 유지하며, 사용자 취소 대상 주문을 대체 매수하거나 같은 과거 신호로 다시 주문하지 않는다.

## 2단계: 다른 종목까지 차단하는 범위 축소

이 단계는 위험 계산 변경이므로 1단계와 별도로 검증·적용한다. 단순히 `reconciliationRequired` 검사를 삭제하지 않는다.

- 동일 종목의 미확인 주문은 계속 중복 매수를 막는다.
- 다른 종목은 미확인 주문의 최대 체결 가능 수량·지정가·손절 기준을 확인하고, 최신 잔고/현금과 중복 계산 없이 최대 자금 및 위험을 예약할 수 있을 때만 검토한다.
- 주문번호가 없는 송신 불명, 시장가의 무제한 가격 위험, 손절 기준 누락, 잔고/현금 불일치, 정정 주문 연결 불명은 소유자 단위 차단을 유지한다.
- 예약한 자금과 위험은 기존 한도를 낮추는 방향으로만 반영한다. 계좌 간 금액 합산은 기존 통화·계좌 소유자 범위를 유지한다.
- 미확인 종목이 실제 보유로 넘어간 경우 예약 위험과 보유 위험을 한 번만 계산한다. 이 연결이 불가능하면 차단한다.

## 사용자 표시

기존 주문 카드에 원인 주문, 조회 결과, 영향을 받는 신호, 유효기간과 취소 진행 상태를 표시한다. 같은 장애를 새 메시지로 계속 발송하지 않는다. 기한 만료나 사용자 조치가 필요한 상태 변화는 숨기지 않는다. 별도 Codex 정기 감시는 재생성하지 않는다.

## 검증 및 적용 기준

기존 테스트 파일과 합성 응답을 재사용한다. 실제 매수는 회귀 테스트에 포함하지 않는다.

1. 같은 종목 미체결은 중복 주문 0건.
2. 다른 종목 확인 지연은 inbox에 남고, 유효기간 내 복구 시 정책 재평가 후 최대 1회 송신.
3. 만료 또는 이후 청산 신호가 있으면 복구 후에도 송신 0건.
4. 부분 체결·취소 접수·취소 거절·취소 응답 유실·재시작에서 기존 체결량 보존 및 재전송 0건.
5. 과거 접수 행만 반복되거나 현재 목록이 비어도 종료 상태를 위조하지 않음.
6. 한 주문 조회 실패가 다른 주문 대조를 중단하지 않음.
7. 미확인 위험의 보수적 예약 및 실제 보유 전환 시 이중 계산 방지. 계산 불가능 시 차단 유지.
8. 계좌/모의·실계좌 분리, 원 신호 마감 시각 및 기존 가격·수량·손절 한도 유지.

먼저 1단계의 회귀 테스트를 통과시키고, 모의 실행기에 적용해 상태 전이를 확인한다. 2단계는 자금·위험 예약 테스트까지 통과한 뒤 별도로 적용한다. 실계좌 잠금은 변경하지 않는다.
